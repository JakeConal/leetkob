# Backend comparison — NestJS PA#2 vs Go compatpub

Generated by `npm run compare:backends` on 2026-11-23 at revision `d527009` on `codex/implement-pa3-go-prototype`. The machine-readable artifact of any rerun is [`backend-comparison.json`](backend-comparison.json); this page is written by the same run, so the two cannot drift. Recorded for issue #38 task 1.5.

## Method

The same seeded publication workload runs against both compositions in process on loopback: 200 warmup replays, then 5 rounds in which each of 200 labs is published, replayed, concealed cross-class 404'd and forbidden 403'd, followed by a 100-request concurrent different-key wave on one fresh lab — 4,680 requests per side. Both sides run their own HTTP stack with a fixed clock and synthetic tokens; latency includes the client call. Build times are warm-cache single runs, not cold-cache measurements. The comparison covers the shared publication contract only (`docs/contract/fixtures/publication-scenarios.json`); the PA#3 judging pipeline has no NestJS equivalent to compare yet.

## Interpretation and acceptance

The Go composition serves the identical contract workload with zero
errors and materially higher throughput. This is parity evidence for the
publication contract only; it is not a judging-pipeline benchmark and not
a production load test.

**Review acceptance: pending.** This comparison does not switch the
default backend: `apps/api` remains the assessed PA#2 application and the
Go production routes stay on their explicit development port (design
decision 1 of `implement-pa3-go-prototype`). A default cutover would be
its own reviewed decision after the PA#3 flow is complete.
