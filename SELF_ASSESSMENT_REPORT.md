## What we did not manage

- The spending cap is an application-level policy (`MODEL_SPENDING_CAP_USD`, USD 0.25 per lab). PA#2 makes no model calls, so no provider key exists yet and no cap is set on a provider dashboard; that happens when the key is created in PA#3.
- Branch protection is evidenced by a captured API response in [`docs/evidence/main-branch-protection.json`](docs/evidence/main-branch-protection.json), not a screenshot. Only `Lint`, `Format`, `Typecheck` and `Test` are required; `Build` and `Security` run on every pull request but are not required.
- Two of the rules-file lines (D1, D2) trace to assistant suggestions we rejected rather than to a failure that reached the repository; only D11 records a real defect.
- Durable storage, production OAuth/OIDC, the C++ sandbox, model calls and deployment are outside this checkpoint. The dashboard review rows are demonstration data.

## What we would do differently

Write the product-owner FAQ into the contract before implementing. The deadline precondition (FAQ-12) was missing from contract v1.0 and had to be added as v1.1 after the code was already merged.
